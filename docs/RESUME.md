# Resume bullets

Honest phrasing you can paste into a resume or internship application. The real-data numbers come from about 1.9 hours of chaos experiments on a single-node kind cluster, scored on a separately collected held-out run. That is not production traffic, so keep the qualifier if you cite them. The pod-kill numbers come from a third run (63 min) collected after the detector rules were frozen. The LLM eval numbers come from one run per model on 38 incidents, so the 95% intervals are about ±15 points. The held-out numbers come from one gpt-oss-120b run on 12 incidents (95% interval for 11/12 is roughly 65–99%), so don't quote them as a precise accuracy.

- Built **Kube Copilot**, an open-source AI incident copilot for Kubernetes: a FastAPI service collects pod status, events, and logs, retrieves the closest runbooks and past incidents from Qdrant (FastEmbed, CPU-only), and streams a Groq LLM diagnosis with citations to a Next.js dashboard.

- Built a chaos-engineering data pipeline (Chaos Mesh on kind plus the Prometheus range API) that labels per-pod metrics during CPU stress, memory stress, memory-leak, restart-storm and pod-kill experiments, and used it to retrain an Isolation Forest anomaly detector on real cluster data with a time-based, leakage-free split and MLflow tracking.

- Found that the synthetic-trained model flagged nearly every real pod (specificity 0.001), then added an out-of-range guard and real-data training. On a held-out run, the detector reached precision 0.85, recall 0.59 and F1 0.70 on application pods, up from F1 0.19 for the synthetic model on the same pods. CPU-stress and restart-storm recall was 1.0, while pod-kill recall stayed low (0.04) because a killed pod simply vanishes from its metrics.

- Added a pod-disruption detector driven by Kubernetes events and lifecycle state (unexplained pod replacements, replica dips, restarts, Killing/BackOff/OOMKilling events), recorded alongside the metrics during chaos runs, and merged it with the Isolation Forest in the API. On a held-out 63-minute run, pod-kill recall went from 0.04 to 0.85, and combined recall on application pods went from 0.33 to 0.82 (F1 0.41 to 0.67, precision 0.57).

- Added human-in-the-loop remediation: the LLM proposes fixes through function calling restricted to four actions (rollback, restart, bounded scale, delete a crashlooping pod), a policy engine in code blocks anything else, each change is dry-run on the Kubernetes API server and shown as a diff, and nothing runs until a person approves it. The service then verifies recovery and writes an audit log, and Helm grants write RBAC only per allowed namespace and only when the feature is turned on. In 12 fault-injection trials on kind, all 9 approved rollbacks were verified as resolved; in the full-outage case the service was healthy 3.3 to 11.7 s after approval.

- Built an LLM evaluation harness for the copilot. It uses 38 Kubernetes incidents reproduced on kind (image pulls, crashes, bad config, missing ConfigMaps/Secrets, OOM kills, probes, scheduling, PVCs, DNS, Chaos Mesh pod kills, healthy pods), hand-labelled from the injected fault and frozen as replayable fixtures, with deterministic scorers, model-free baselines and an optional LLM judge that is checked against hand labels. On Groq gpt-oss-120b, Diagnose found the root cause in 30/38 incidents (hand-checked; 27/38 by a strict regex matcher, 92% agreement), the remediation agent chose an acceptable action in 30/38, 97% of replies were valid JSON, and no kubectl command referenced a resource that wasn't in the evidence. The eval surfaced a real bug: the agent never saw config diffs between revisions, so it declined 7 valid rollbacks. I fixed it with a field-level pod-template diff between ReplicaSet revisions, and added CPU-throttling metrics, structured pod-kill signals and a token budget for logs. On 12 held-out incidents written and captured after the prompts were frozen, Diagnose found the root cause in 12/12 (hand-checked) and the agent chose an acceptable action in 11/12, with no request errors.

- Packaged the stack for real clusters with a least-privilege Helm chart (in-cluster Kubernetes client, optional Qdrant, probes, and resource limits), GitHub Actions CI (pytest, Helm lint, a kind smoke test, GHCR publish, Trivy scans), a Terraform module for a single-node k3s VM, and Grafana dashboards for pod resources and anomaly scores.

- Wrote 100+ backend tests with mocked Kubernetes, LLM, and Prometheus clients, plus a one-command kind demo that reproduces CrashLoopBackOff, ImagePullBackOff, OOMKilled, and a leaking process.
